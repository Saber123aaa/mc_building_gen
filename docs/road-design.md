# 道路、桥头与路口生成

此改动直接用于场地模式的 `street()` 和布局模式的 `townRoads()`，没有新增精修/简化等质量档位。房屋和建筑风格生成器保持独立。

## 规则

- 桥头按桥面横断面寻找干岸，桥端设置石砌桥台、渐变加宽的引道与外侧翼墙。缺岸或路线太短时报告限制，保留水道。
- 桥面在过水段保持同一高度；栏杆的结构宽度另行预留，含45度栅格化所需余量。木梁按道路切线选择横向轴。桥面支路入口清理成为内部的旧栏杆，外缘继续防护。
- 交叉路口在原有转角铺装和路缘整理之外增加中心平台，外边界固定，通过高度区间传播检查是否能平顺接回原路。两格长度最多爬升一格，避免连续半砖被挤成整格跳跃。桥面与不可行的短引道保留原坡道并报告。
- 道路纵断面在端点、明显折角和桥头优先留平缓段；升降有额外代价，以减少无意义的连续起伏。桥面平整和已有路口高程是硬约束；休息平台空间不足时可缩短，已有路口约束冲突时跳过该道路并提示。
- 半砖依据实际相邻路面高度布置，而非只看最近的中心线索引。路口调整后的高程会传给后续房屋、台基和路灯定位。
- 过滤无效点和重复点，处理180度回折圆角、越界路线与负坐标；无法生成时不修改地形。

## 验证

```powershell
python web/build_js.py
node web/test/road-design.cjs
python build_viewer.py
```

`road-design-cases.cjs` 有30个固定场景，可由相同输入生成改动前后的模型；测试另有144个宽度、曲线、地形和路径组合，以及无效输入、不可行路口高程、180度回折与确定性检查。

检查覆盖横向越界、路面相邻高度、桥面平整和由半格碰撞高度建立的四邻通行路径。它证明每条展示路线有连续通路，不代表路面每一格都可通行，也不代替游戏内实走。平顺平台可能增加挖填量，报告保留实际土方数。

原有292组房屋JS/Python一致性检查、巴洛克大模型放置与旋转回归通过。网页另验证场地后台生成、布局工程重开、导出回读，以及对比模型渲染和同步视角。
