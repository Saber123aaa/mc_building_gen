# mcgen：参数化 MC 建筑生成器原型

思路：大模型只输出高层设计参数（`specs/*.json`），代码组件负责把参数翻译成好看的方块。

## 产品形态：一个网页文件

`viewer/index.html` 就是完整的产品：生成器（JavaScript）、3D 预览、换色、导出 .schem 全在这一个文件里（约 400 KB），
不加载任何外部资源（没有 CDN、没有在线字体），断网也能用。

- **给别人用**：把 `viewer/index.html` 放到任意静态托管上，别人打开链接就能用，例如
  - Gitee Pages / GitHub Pages：建一个仓库，放进去改名 `index.html`，开启 Pages；
  - 阿里云 OSS / 腾讯云 COS：建一个公共读的存储桶，开启静态网站托管，上传即可；
  - 也可以直接把文件发给别人（微信、网盘），双击用浏览器打开。
- **更新**：改完代码运行 `python build_viewer.py`，把新的 `viewer/index.html` 覆盖上传，所有人刷新就是新版。
- **方块纹理**：侧栏"方块纹理"可以载入游戏 jar（`.minecraft/versions/版本/版本.jar`）、资源包 zip 或解压后的 `textures` 文件夹，预览就用真实纹理；纹理只存在使用者自己的浏览器里（IndexedDB），页面本身不含任何游戏素材，可以放心分发。
- 页面里点"导出 .schem"直接下载文件（在 claude.ai 的预览页里会打包成 .zip）。

## 生成的文件不进仓库（拉代码后先生成一次）

`viewer/index.html`、`web/mcgen.js`、`web/mcgen_data.json` 都是从源码生成的，**不再提交到 git**——以前每个分支都会改它们，
合并时必然冲突。现在：

- **第一次**：运行一次 `scripts\setup-hooks.bat`（macOS / Linux：`sh scripts/setup-hooks.sh`）。它会生成一次页面，
  并让以后每次 `git pull`、切换分支、合并之后自动重新生成，什么都不用管。
- **不想用自动生成**：拉代码后双击 `scripts\build.bat`（或运行 `python build_viewer.py`）。
- **直接用最新版**：main 上每次合并后，GitHub Actions 会自动生成并发布到 GitHub Pages：
  https://edwinlee-371.github.io/mc_building_gen/ ；每个 PR 的检查结果里也能下载 `mcgen-viewer`（生成好的页面）。
- **新增源码文件**：`web/src/` 下新加的 `.js` 会被自动打包、顶层的函数和常量自动导出，不用改 `web/build_js.py`。
  只有当新文件的顶层代码在载入时就要用到别的文件的常量，才需要把它写进 `ORDER`。

## 开发

生成器的主实现是 `web/src/*.js`（从 Python 版逐行移植，同一个种子生成的房子逐格相同）：

```bash
python build_viewer.py                          # 一条命令全部生成：web/mcgen.js、web/mcgen_data.json、viewer/index.html
python web/build_js.py                          # 只生成 web/mcgen.js 与 web/mcgen_data.json（Node 与测试用）
node web/cli.js specs/plan_L.json out/L.schem   # 命令行生成 .schem（Node.js，无依赖）
```

`mcgen/`（Python）保留为参考实现和一致性测试的基准（见 `web/test/README.md`）：改了生成规则时，两边一起改，
再跑一遍一致性测试；以后也可以只维护 JS 版。`python generate.py specs/xxx.json out/xxx.schem` 仍然可用。

生成的 .schem 是 Sponge v2 格式（DataVersion 3953，即 1.21），WorldEdit / FAWE 可以直接 `//schem load`。
预览器也能打开任意 .schem / .litematic / 原版结构 .nbt，支持剖切看内部。

## 结构

| 文件 | 作用 |
| --- | --- |
| `mcgen/structure.py` | 方块容器 + .schem 写出（手写 NBT，无依赖） |
| `mcgen/palettes.py` | 人工调好的色板，每个槽位是加权混合，避免大面积单一材质 |
| `mcgen/proportions.py` | 比例规则：屋顶/房体、山墙高/宽、平面长宽比；超出范围时按“改动最小”自动校正并输出说明 |
| `mcgen/transform.py` | 斜向房屋：按台阶模板把整栋房子斜放（双剪切，一一对应，不留空洞） |
| `mcgen/layout.py` | 多体块户型：体块规划、转向放置、合并规则、全局门 / 烟囱 / 地面 |
| `mcgen/check.py` | 漏缝检查：从外部灌空气，看能不能进到室内 |
| `mcgen/annex.py` | 附属建筑：披屋 / 柴房 / 马厩 / 铁匠铺 / 楼梯塔（体块）和门罩 / 门廊 / 凸窗（构件），功能预设 |
| `mcgen/colors.py` | 指定颜色换色：从方块色板里为屋顶 / 墙面 / 木构 / 基座挑最接近的原版方块 |
| `web/src/*.js` | 生成器的 JavaScript 版（主实现）：`py.js` 是与 CPython 一致的随机数 / 哈希 / 取整，其余文件和 Python 模块一一对应 |
| `web/cli.js` | 命令行生成 .schem |
| `mcgen/data/mc_block_palette.json` | 方块色板数据（贴图平均色、OKLCH、色系、类型） |
| `mcgen/house.py` | 组件：基座、木框架楼层（柱子外凸、填充墙内凹）、出挑二层（jetty + 托架）、窗（窗台 + 宽开间才加百叶）、门 + 台阶、山墙屋顶（挑檐 + 檐下倒台阶 + 屋脊半砖 + 山墙木构）、烟囱、地面和植物 |
| `specs/*.json` | “大模型输出层”示例（含 4 种屋顶对比） |

## 比例规则

生成前，spec 先经过 `proportions.solve()` 检查三个比例（中世纪风格的合理范围）：

| 比例 | 含义 | 合理范围 |
| --- | --- | --- |
| 屋顶/房体 | 屋顶高 ÷ 墙身高（含基座） | 0.45–1.0 |
| 山墙高/宽 | (墙身高 + 屋顶高) ÷ 山墙跨度 | 0.8–1.8 |
| 平面长宽比 | 面宽 ÷ 进深（屋脊沿长边） | 1.0–2.2 |

超出范围时，在“层高、出挑、飞檐、坡度”中搜索改动代价最小的组合。改坡度代价最高，所以要求陡坡时会先加高房体，实在不行才降坡。每处改动都会写进报告。`--raw` 可以跳过校正。层数始终保留输入值，层高仍可能自动调整。网页的层数输入和编辑支持 1–5 层；四层及以上会显示黄色造型提示图标，中世纪民房建议使用 1–3 层。

## 窗户分布

不是每个开间、每面墙都开窗。每个开间先决定角色：门、窗，或者保持普通墙面。
- 开窗概率按立面不同：正面（北）0.7，背面（南）0.45，两侧山墙面各 0.35。概率写在 `HouseBuilder.WINDOW_P`。
- 采光保底：每层正面至少 1 扇窗，整层至少 2 扇。
- 开间少于 3 格时不开窗。
- 结果由 `seed` 决定，换 seed 就是另一种开窗分布。

## 屋顶样式（roof_style）

屋顶统一描述成一个剖面：每一列给出南北两半的高度，单位是半格。再由同一个栅格化器生成方块：
- 平顶放满方块，坡度半格放台阶，坡度一格或以上放楼梯；
- 每列往下填到相邻列的顶，陡列至少填到自己低侧那一半的高度，保证不漏缝；
- 半格坡（缓坡、盐盒长坡、蝴蝶、单坡）的层级按参考图：
  - 缓坡：屋面带厚一格，一列是满方块，下一列是"上半台阶 + 下半台阶"错开半格，交替往下；山墙那一格的上半台阶用满方块，避免墙面出现半格洞；奇数跨度的屋脊多升半格，形成尖顶。
  - 单坡：每列只有一块台阶，下半台阶与上半台阶交替，屋面薄，下面的墙体补到屋面底。
  - 盐盒：短边用楼梯，长边用缓坡的半格节奏。
- 屋顶底面用满方块按台阶往下填（挑出那一排和山墙那一排同一形状），山墙墙面正好补到屋顶底面，不凹也不凸。倒置楼梯补底面（`underside_stairs`）默认关闭；
- 山墙、檐口较高的长墙都自动用墙体填到屋顶底面。

| roof_style | 样式 | 适合 |
| --- | --- | --- |
| `gable` | 双坡，坡度按 `roof_pitch`（low 台阶 / normal 楼梯 / steep 方块+楼梯），可加飞檐 | 民居 |
| `gambrel` | 复折：下段陡、上段缓 | 谷仓、农房 |
| `mansard` | 孟莎：四周近乎竖直，顶部平 | 城镇屋 |
| `curved` | 拱顶 | 仓库、温室 |
| `saltbox` | 盐盒：不对称，一侧短陡、一侧长缓 | 民居、农舍 |
| `mono` | 单坡 | 附属建筑、披屋、棚 |
| `clerestory` | 高侧窗：两段单坡错开，中间一段带窗的竖墙 | 作坊、礼堂 |
| `m_shaped` | M 形双峰 | 宽房、联排 |
| `butterfly` | 蝴蝶：中间低两侧高 | 特殊建筑 |
| `elven` | 精灵：檐口缓、越往上越陡（内凹） | 奇幻风 |
| `temple` | 神庙：缓坡加陡顶（内凹，较矮） | 神庙、亭 |
| `magical` | 魔法：内凹并收成尖顶 | 法师塔、奇幻风 |

要加新样式，只需在 `HouseBuilder.roof_columns()` 里写出它的剖面，其余由栅格化器处理。

## 户型（plan）与体块

房子由体块组成。每个体块都是一栋普通的房子（自己的层数、出挑、屋顶、开窗），在局部坐标里建好（屋脊沿 x），再转 0/90/180/270° 放到位置上。

| plan | 户型 | 体块 |
| --- | --- | --- |
| `rect` | 长方形 | 主屋 |
| `L` | L 型 | 主屋 + 一端的横翼（山墙朝街，向前凸出 3–6 格） |
| `T` | T 型 | 主屋 + 中部横翼（多数向后，少数向前凸出） |
| `H` | H 型 | 主屋 + 两端横翼；向前、向后凸出多少由种子决定（0–5 格，至少一侧 ≥3），向前为 0 时就是只向后凸出、围出后院的样子 |
| `cross` | 十字 | 主屋 + 对穿的横向体块，四臂等长 |
| `cross_long` | 十字架（X 型） | 同上，但一臂明显更长 |
| `longhouse` | 长屋 | 主屋 + 同轴接在一端、更矮的牲口棚 |
| `auto` | 由种子选 | 小房子多为长方形 / L 型，大房子才可能出现 H、十字 |

合并规则：
1. 屋顶更高的体块占主导，相同高度时按角色排序：端部横翼 > 主屋 > 中部翼 > 附属。
2. 垂直相接时，较低的体块在高体块的屋脊线处截断，它的屋顶伸进高屋顶底下，两个屋面形成斜沟；如果两边都穿出去（十字），就不截断，两个屋顶直接相交。
3. 同轴相接（长屋）时，较低体块伸进高体块的部分整个去掉。
4. 每个体块的房间内部只保留它自己的方块，所以相连的体块是打通的，没有多余的墙、楼板或屋顶残片；如果某格原本是它自己的墙被别的体块盖掉了，就恢复成它自己的墙。
5. 落在别的体块内部、或者正对着别的体块的窗户改成墙；落在别的体块里的窗台、百叶、灯笼去掉，并把那一格还给原来的墙。
6. 门、烟囱、地面对整栋房子统一放置：门开在主屋临街一面、没有被翼楼挡住的开间里，必须通向室内、门外是空地。

用 `mcgen/check.py` 的漏缝检查对 5 种风格 × 7 种户型 × 5 个种子共 175 栋房子跑过，全部没有漏缝。

## 附属建筑（annexes）与功能（function）

只做外观、不做内饰；敞开的附属建筑里放几样能从外面看到的物件。

| 名称 | 位置 | 做法 |
| --- | --- | --- |
| `storage` 披屋（储物） | 一楼，背面或山墙一侧 | 单坡顶靠在主墙上，有自己的门 |
| `woodshed` 柴房 | 一楼 | 正面敞开的披屋，里面堆柴、放一个劈柴墩 |
| `stable` 马厩 | 一楼，优先山墙一侧 | 正面敞开，栅栏门围栏，中间隔栏，干草块 |
| `smithy` 铁匠铺 | 一楼，优先山墙一侧 | 正面敞开，高炉、熔炉、铁砧、砂轮、炼药锅，自带锻炉烟囱 |
| `tower` 楼梯塔 | 背面，贯通各层 | 5 格宽的窄体块，比主屋多一层，陡坡或魔法尖顶 |
| `hood` 门罩 | 一楼门上方 | 一排楼梯小屋檐，两侧活板门做托架 |
| `porch` 门廊 | 一楼门前 | 石地台和台阶，两根柱子，小双坡顶 |
| `oriel` 凸窗 | 二楼正面 | 在一个开间里向外凸出一格，底下托架，正面玻璃，顶上楼梯小檐 |

- 体块类附属（披屋、柴房、马厩、铁匠铺、楼梯塔）和翼楼一样作为体块建造，再并入整栋房子；披屋的单坡顶从主墙往外压低，高度按主屋墙高自动定。
- 放置规则：铁匠铺、马厩优先放在没有翼楼的山墙一端；其余放在背面没有被翼楼占用的墙段上，互相不重叠。放不下就跳过，报告里会写实际放了哪些。
- 门罩和门廊在门确定以后再加；门开在出挑下面时不加（出挑本身就能遮雨），改挂一盏灯笼。凸窗在二楼正面挑一个 3–5 格宽、没有被翼楼挡住的开间。
- 老虎窗现在只放在主屋上，并避开翼楼和楼梯塔的位置。

`function` 决定各类附属出现的概率（由种子抽取），`annexes` 写成列表时直接指定：

| function | 常见附属 |
| --- | --- |
| `dwelling` 住宅（默认） | 门罩 / 门廊、凸窗、披屋、柴房，偶尔楼梯塔 |
| `smithy` 铁匠铺 | 铁匠铺必有，加门罩、柴房、凸窗 |
| `farm` 农舍 | 马厩、柴房、披屋、门廊 |
| `tavern` 酒馆 | 门廊、凸窗、马厩、楼梯塔 |

## 指定颜色换色（colors）

```json
"colors": {"roof": "#4a4a4a", "wall": "米黄", "wall_ground": "砖红", "frame": "浅棕", "base": "深灰"}
```

- 值可以是 `#rrggbb`，也可以是颜色词：白、米白、米、米黄、浅灰、灰、深灰、黑、红、砖红、深红、橙、黄、金、绿、深绿、青、蓝、深蓝、浅蓝、紫、粉、棕、深棕、浅棕、木色、沙色、石色。只写一部分也可以，其余沿用风格色板。
- 每个部位只在"放得上去"的方块里挑，按 OKLab 色差找最近的：
  - 屋顶：同时有完整方块、楼梯、台阶的材质；
  - 木构：原木 / 菌柄（含去皮），同时换掉对应的楼梯托架、门、活板门、栅栏；
  - 墙面：石材、木板、羊毛、混凝土、陶瓦、铜等完整建材（不含带釉陶瓦、矿石、功能方块、1.21.10 之后新增的方块）；
  - 基座：有楼梯的石材，门前台阶一起换。
- 主方块之外，最多再混入 2 种同材质家族、色差小于 6 的方块（权重 6:2:1），保留成片斑驳的效果，比如石砖 + 苔石砖 + 裂纹石砖。
- 报告里会写出每个部位选中了哪些方块和色差 ΔE；ΔE 超过 8 时会提示原版没有更接近的方块（比如亮蓝色屋顶，最接近的只有诡异木板）。
- 预览器侧栏有"换色"面板：对生成器示例可以直接用取色器改五个部位的颜色，算法和生成器一致，实时替换方块。预览器里的方块颜色也改成了色板里的真实贴图平均色。

### 混色：色阶 + 混合方式

部位的值写成对象，就会从选中的颜色出发做一条"暗 → 亮"的色阶，再按位置决定每格用色阶里的哪一块：

```json
"colors": {
  "roof": {"color": "#4a4a4a", "style": "bottom_dark", "range": 24, "count": 4, "cross": true},
  "wall": {"color": "米黄", "style": "weathered", "range": 14},
  "base": {"style": "weathered", "range": 18, "count": 3}
}
```

| 字段 | 含义 | 默认 |
| --- | --- | --- |
| `color` | 色阶中心色；不写就用风格色板原有用料的平均色 | — |
| `range` | 明暗跨度：色阶最暗到最亮的亮度差（OKLab L×100），越大对比越强 | 14 |
| `count` | 色阶里放几种方块（2–6） | 4 |
| `style` | 混合方式，见下表 | `cluster` |
| `jitter` | 边缘打散（0–0.8）：渐变带的边缘按斑块噪声错开，避免一条条"夹心"横纹 | 0.35 |
| `scale` | 斑块大小（1–5） | 2 |
| `curve` | 渐变曲线：`linear` 均匀 / `ease_in` 先慢后快 / `ease_out` 先快后慢 / `ease_in_out` 两头缓 / `step` 分段 | `linear` |
| `cross` | 允许跨材质 | `false` |
| `skip` | 偶尔跳一级色阶，增加局部对比（0–0.3） | 0 |

| `style` | 效果 |
| --- | --- |
| `cluster` 成片随机 | 主色占多，其余按亮度远近成片混入 |
| `speckle` 细碎随机 | 同上，但逐格打散 |
| `bottom_dark` 上浅下深 / `top_dark` 上深下浅 | 按该部位自身的高度范围渐变 |
| `horizontal` 左右渐变 | 沿长边渐变 |
| `weathered` 风化 | 墙脚、转角、门窗四周和窗下"雨痕"偏暗，其余成片混合 |
| `eave_dark` 檐口深 / `ridge_dark` 屋脊深 | 屋顶用：檐口压暗或屋脊压暗 |

- **同家族（默认）**：只在同一材质家族里选，比如石头 / 圆石 / 苔石 / 石砖 / 平滑石头，或同一染色的混凝土 / 混凝土粉末 / 羊毛 / 陶瓦。
- **跨材质**：改为挑色相、饱和度接近的所有可用方块（不够时逐步放宽），合并后**再按亮度重新排序**，所以色阶始终是暗 → 亮的顺序。
- 屋顶的色阶是"完整方块 / 楼梯 / 台阶"三件套整体对齐的，同一格位置的楼梯和台阶一定同材质。
- 报告会列出色阶、实际明暗跨度和相邻两级的色差；找不到足够的方块时会提示加大跨度或打开跨材质。
- 只写颜色字符串时保持原来的行为（最近的方块 + 两种同家族陪衬，6:2:1）。

## 老虎窗（dormers）

老虎窗就是屋面上的小屋顶，屋脊和主屋脊垂直。它的剖面直接复用主屋顶的 `roof_columns()` / `raster_roof()`，只是横着铺在 x 方向上，所以屋顶样式基本都能用在老虎窗上：

| dormer_style | 样式 | 前墙宽 |
| --- | --- | --- |
| `gable` | 标准坡（楼梯） | 3 |
| `steep` | 陡坡（方块 + 楼梯），窗更高 | 3 |
| `low` | 缓坡（台阶半格节奏） | 5 |
| `curved` | 拱形 | 5 |
| `mono` | 单坡 | 3 |
| `temple` | 神庙式（内凹） | 5 |

- 前墙只用木头和玻璃：两侧柱子一直立到小屋顶底面，中间是玻璃，也一直到小屋顶底面；5 格宽的在中间多加一根窗棂柱。
- 窗台是下半活板门，贴在窗户底边的下方。
- 小屋顶比前墙两边各宽 1 格做挑檐；最前面挑出的一排只放每列最上面那一块，形成轮廓。
- 老虎窗往屋面里延伸，直到主屋面高过小屋顶为止，两个屋面在交界处形成斜沟；背后的主屋顶被挖空，两侧补墙。
- `"dormers": "auto"`（默认）由种子决定数量和位置，正面坡 0–2 个、背面坡 0–1 个；`0` 表示不加；数字表示正面坡上的个数。`"dormer_style": "auto"` 时由种子挑一种样式，同一栋房子的老虎窗样式统一。会自动避开烟囱和山墙。
- `"dormer_gap"`：相邻老虎窗之间空几格，从一个的挑檐边量到下一个的挑檐边。`0` 是紧挨着，数字越大离得越远；设了数字时，这一组老虎窗会居中排在坡面上，放不下就自动减少个数。默认 `auto` 是均匀分布在整个坡面上。
- 屋顶太矮或坡太缓、放不下时自动不加。

## 斜向房屋（rotation）

`"rotation": 26` 表示斜放 26°。可选角度和对应的台阶节奏（长边，也就是屋檐那一侧）：

| 角度 | 长边节奏 | 角度 | 长边节奏 |
| --- | --- | --- | --- |
| 12° | 每 5 格一阶 | 78° | 每 5 格一阶 |
| 15° | 每 4 格一阶 | 75° | 每 4 格一阶 |
| 20° | 每 3 格一阶 | 70° | 每 3 格一阶 |
| 26° | 每 2 格一阶 | 64° | 每 2 格一阶 |
| 33° | 2 格、1 格交替 | 57° | 2 格、1 格交替 |
| 45° | 每格一阶 | 负角度 | 往另一个方向斜放 |

- 先按正常方式建好整栋房子，再用两次整数剪切把每一列方块挪到斜向位置：先按行平移，再按列平移。每个方块一一对应，不会出现空洞或重叠；墙、屋顶剖面、门都是整列一起移动，竖直结构保持不变。
- 长边严格按模板节奏走；短边（山墙一侧）用补偿后的剪切率并居中取整，和长边基本垂直（夹角 84°–92°），节奏接近模板。
- 斜放后长边的真实长度会变长、短边变短，所以会先缩放本地尺寸，保证成品的真实尺寸仍是 spec 里的宽×深。长边会取成台阶周期的整数倍，这样墙角正好落在完整的一阶上。
- 斜放时墙改成柱、墙齐平，窗台和百叶挂在墙外侧。原来的一格内凹在斜墙上会变成错位，柱子看起来像浮在墙外。
- 斜放时窗户（包括山墙窗）一律用玻璃块。玻璃板只能和前后左右四个方向的方块相连，墙一错阶就会露缝。
- 斜放后，门两侧和门顶上方如果是空格，会用基座石材（与基座同一套斑驳规则）补上，防止墙线错阶时门边漏出缝隙。
- 斜放后会按相邻方块重新计算栅栏的连接状态。
- 小角度（12°–26°）效果最好；33°、45° 屋顶的视觉坡度会变陡一些。

## 楼梯转角

WorldEdit / Litematica 粘贴时不会触发方块更新，楼梯会保持文件里写的形状。所以生成器在最后一步按游戏自己的规则（`StairBlock.getStairsShape`）算好每块楼梯的 `shape`（直 / 内角 / 外角），粘贴后就是正确的转角，之后游戏里再有方块更新也不会变：

- 被上方屋顶压住的楼梯换成同材质的完整方块（它看不见，留着反而会挡住旁边楼梯形成转角，从侧面看还会露出缺口）；
- 侧翼屋脊、老虎窗顶伸进主屋顶坡面的那一段，坡面楼梯换成完整方块，让屋脊延伸进坡面，两侧的天沟楼梯就能变成内角；
- 预览器也按 `shape` 画出内角 / 外角楼梯。

## 地形、组件、场地与街区（测试版，只有 JS 实现）

| 文件 | 作用 |
| --- | --- |
| `web/src/terrain.js` | 从地形 .schem 读出高度图、水面；`setGround` 挖方 / 填方并记账；`summary()` 统计挖填量；`synthTerrain` 生成测试地形 |
| `web/src/props.js` | 组件：路灯（单臂 / 双臂 / 石柱 / 木桩）、树（橡树 / 白桦 / 云杉 × 大中小，树叶 persistent）、井（石砌 / 带顶）；`placeProp` 带转向放置；`checkPlacement` 放置合法性检查（树叶、灯笼挂点、花草土壤、重力方块、漏水、门） |
| `web/src/site.js` | 场地生成器：道路贴地形。中线限坡（每 3 格最多升 1 格），挖填到路面，两侧 2 格过渡回自然坡，爬坡处放台阶半砖，沿路放路灯和行道树 |
| `web/src/town.js` | 布局层：一片街区。选挖填最少的主街走向，选最平的一段做集市广场（水井 + 石柱灯 + 树），两侧划窄长地块，每块地在挖填预算内找房基高度，房子正门朝街并铺小路接到街上；超预算的地块留作绿地 |

网页"场地"栏可以"显示地形"后在 3D 视图里依次点击路线点，按点选的路线铺路；"布局"栏可以框选一个矩形区域，只在区域内生成街区，结果再拼回整块地形。
网页侧栏"布局"：选示例地形或"当前载入的模型"，设最大挖深 / 填高、主街宽、风格，生成后导出。
载入的地形 .schem 的 `Offset` 和 `WEOffsetX/Y/Z` 会原样写回导出文件，所以可以 `//schem load` 后 `//paste -o` 贴回原位；
不要加 `-a`，否则挖掉的地方不会被清空。

还没做：多条街和支巷、弯曲街道、过河的桥、房子以外的公共建筑、广场以外的集市摊位、大模型调用接口。

## 种子（seed）

所有随机内容都由 `seed` 决定，同一个 seed 每次生成的结果完全一样，逐块相同。
- 主 seed 会派生出互相独立的随机序列：`windows`（开窗分布）、`materials`（材质斑驳）、`plants`（花草）、`dormers`（老虎窗）、`layout`（户型和翼楼尺寸）、`annexes`（附属建筑的种类和位置）。改动其中一项的规则，不会打乱其他项。
- 斑驳是成片分布的：方块按带抖动的格子聚成不规则的斑块，屋顶的楼梯和满方块共用同一组斑块，各材料所占比例仍然符合色板权重。斑块大小在 `HouseBuilder.NOISE_SCALE` 里调。
- 可以用 `"seeds": {"materials": 42}` 只替换某一项的种子，比如保留开窗、只换墙面斑驳。
